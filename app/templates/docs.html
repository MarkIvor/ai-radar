1. Авторизация

AI Radar поддерживает два типа учётных данных:

ТипНазначениеЗаголовокСрок жизни
Session JWTДоступ человека через UIAuthorization: Bearer <jwt>30 мин (refresh: 7 дней)
API KeyПрограммный доступAuthorization: Bearer air_...
или X-API-Key: air_...		Бессрочно (до revoke/rotate)

Логин мастер-паролем

POST /api/auth/login
Content-Type: application/json

{"password": "airadar"}

Ответ:

{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "Bearer",
  "expires_in": 1800
}

Обновление токена

POST /api/auth/refresh
{"refresh_token": "eyJ..."}

Проверка текущего субъекта

GET /api/auth/whoami

Возвращает {"type": "session"|"api_key", "name": "...", "is_admin": true}.

2. Экспресс-сканирование

Без сохранения в папки. Два варианта — файлом или JSON-текстом.

Вариант A: JSON-текст (для скриптов)

POST /api/scan/quick/json
Content-Type: application/json
Authorization: Bearer air_...

{
  "text": "В современном мире важно отметить...",
  "title": "my_work.txt"
}

Вариант B: файл (multipart)

POST /api/scan/quick
Authorization: Bearer air_...
Content-Type: multipart/form-data

file=@thesis.docx
title=thesis.docx

Поддерживаются форматы: .txt, .docx, .pdf. Лимит — 10 МБ.

3. Глубокая проверка

Запускается для файла, ранее загруженного в хранилище.

POST /api/scan/deep/{file_id}
Authorization: Bearer air_...

5. Отчёты

GET /api/scan/reports/recent?limit=10   # последние N проверок
GET /api/scan/reports/{id}                # полный отчёт по id

Полный отчёт также доступен как HTML-страница: /report/{id}.

6. Админ-управление

Все эндпоинты требуют admin-прав (любой авторизованный пользователь).

МетодПутьОписание
GET/api/admin/settingsТекущие настройки
PUT/api/admin/settingsОбновить (пароль, veto_threshold, judge_mode)
GET/POST/api/admin/llm-providersСписок / добавление LLM-провайдеров
PUT/DELETE/api/admin/llm-providers/{id}Изменить / удалить
POST/api/admin/llm-providers/{id}/toggle?enabled=trueВключить/выключить
GET/POST/api/admin/api-keysСписок / создание API-ключа
DELETE/api/admin/api-keys/{id}Отозвать
POST/api/admin/api-keys/{id}/rotateРотация (старый отзывается)
GET/api/admin/judge-statusСтатус судьи (OFFLINE/ENSEMBLE_ONLY/FULL)

При создании LLM-провайдера укажите role: "ensemble" (детектор) или "judge" (метасудья).

7. Примеры

curl — полный цикл

# 1) Создать API-ключ (через UI-сессию)
ACCESS=$(curl -s -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"password":"airadar"}' | python -c "import sys,json;print(json.load(sys.stdin)['access_token'])")

curl -s -X POST http://localhost:8000/api/admin/api-keys \
  -H "Authorization: Bearer $ACCESS" \
  -H "Content-Type: application/json" \
  -d '{"name":"CI"}'
# => {"key":"air_xxxx..."}  # сохранить, показывается один раз

# 2) Скан текста через API-ключ
curl -X POST http://localhost:8000/api/scan/quick/json \
  -H "Authorization: Bearer air_xxxx..." \
  -H "Content-Type: application/json" \
  -d '{"text":"В современном мире...","title":"work.txt"}'

Python (requests)

import requests

API = "http://localhost:8000"
KEY = "air_xxxx..."

r = requests.post(
    f"{API}/api/scan/quick/json",
    headers={"Authorization": f"Bearer {KEY}"},
    json={"text": "В современном мире важно отметить...", "title": "work.txt"},
)
report = r.json()
print(f"ai_score={report['ai_score']} veto={report['veto']} integrity={report['academic_integrity']}")

8. Формат ответа сканирования

{
  "id": 42,
  "source": "quick",
  "title": "work.txt",
  "ai_score": 82,
  "stat_score": 67,
  "veto": true,
  "veto_reason": "Ансамбль: повторяющиеся клише «таким образом»...",
  "academic_integrity": "НАРУШЕНА",
  "judge_status": "FULL",
  "metrics": {
    "signal1": { "burstiness": 0.21, "lexical_diversity_ttr": 0.42, ... },
    "signal1_interpretation": "ВЫСОКАЯ вероятность ИИ-генерации...",
    "signal2_ensemble_panel": { "ensemble": {...}, "judge": {...} },
    "judge_status": "FULL"
  },
  "suspicious_fragments": ["Таким образом, необходимо отметить", ...],
  "text_preview": "В современном мире...",
  "created_at": "2026-07-26T14:30:00+00:00"
}

judge_status принимает значения:

  • OFFLINE — нет LLM, вердикт только на Сигнале 1, VETO не активируется.
  • ENSEMBLE_ONLY — есть ансамбль детекторов, нет метасудьи.
  • FULL — ансамбль + метасудья, финальный вердикт от судьи.
